# Local demo catalog parity with Android's 72-item fixture

Source reviewed: `feat/rit-complete-frontend-experience` at `be2bf40ba0bf8b42e013c478367093e8b09e6993`, specifically `PreviewCatalog.initialCategories`, `PreviewCatalog.initialSellers`, `PreviewCatalog.initialItems` and `CatalogArtwork.itemPhotos` in `CustomerCatalog.kt`. The frontend branch was **read-only** during this backend integration. Android's `docs/frontend/DEMO_CATALOG_EXPANSION.md` and `DEMO_CATALOG_IMAGE_MANIFEST.md` were also checked. No Android image binary is hosted by the backend.

The auditable source snapshot is `backend/src/main/resources/demo/catalog-categories-v2.tsv` (15 `id, name` rows) and `catalog-items-v2.tsv` (72 rows). Item columns are `id, sellerId, categoryId, name, description, pricePaise, kind, dietary, availability, published, unavailableVisibility, imageKey`. `pricePaise = Android Price(rupees) × 100`; `imageKey = stable item ID` only when `CatalogArtwork.itemPhoto(id)` was present. All 72 Android items have that mapping. `catalog-items-v1-legacy.tsv` records the unchanged historical 12-row Commerce fixture solely to distinguish pristine rows during upgrade; it is not an alternative current catalog.

On a fresh local demo database, `seedCommerceFixtures` creates 4 stable sellers via the core bootstrap, 15 categories, 72 distinct items, **18 each** for `main-canteen`, `north-counter`, `coffee-corner`, and `campus-pantry`, plus only the necessary seller/category mappings. `idli` is Breakfast, `north-lunch` is Combos, `corner-biscuits` is Cookies & Biscuits, and both `pantry-juice` and `pantry-water` are `drinks` / Beverages while remaining `PACKAGED`. `lemon-rice` is the one deliberately unavailable visible item. Main Canteen `PREPARED` items alone have the individual-demo mode; the other items are bulk-only. Seller hours remain unknown until an authorized seller configures them; no opening hours were inferred from the Android presentation.

The seed runs only once per **local-mode startup**, after Flyway, seller and identity bootstrap, and only if `DEMO_SEED_ENABLED=true`. It refuses production/test mode, does not touch accounts/memberships/grants, and uses one transaction. It inserts missing category/mapping/item records with conflict-ignore. It does not overwrite existing seller-edited item values, availability, publication, hours or policy. The two old presentation category labels are refreshed only when their names still equal the old fixture labels. For the original 12 item IDs, a row is upgraded to the new Android values **only if every persisted fixture field still exactly equals the V1 seed row**; any seller modification leaves that row intact. Obsolete old seller/category mappings are removed only when no item uses them. No applied V020 migration was edited and no new DDL was needed, so there is no V060 migration in this checkpoint.

This intentionally yields a distinction: a legacy database with seller customizations may not have byte-for-byte 72-item **value** parity, although it retains 72 item IDs and seller edits. The API is authoritative for that database; do not silently reset it. For a teacher demo requiring pristine exact parity, opt in by provisioning a **new disposable `rit_canteen_dev` database** and starting with local seeding; leave the prior edited database untouched. There is no automatic destructive catalog reset or production seed. A previously deleted original fixture item may be reinserted on a legacy DB because V1 had no item-seed tombstone marker; do not use local fixtures as a production inventory lifecycle.

Verification on PostgreSQL 16.15 used dedicated disposable `rit_canteen_fresh` and `rit_canteen_legacy` databases with a unique schema for every test run. Automated tests asserted exact 72/18 counts, original IDs, `imageKey`, Pantry drink packaging, migration order/checksums, restart idempotence, retention of a seller-edited value/availability, pristine legacy category/name backfill, and preservation of a changed legacy price. The mounted live HTTP smoke compared every item field against the V2 manifest, queried each seller's 18 rows and Pantry Beverages, then restarted the server and confirmed catalog persistence. Prices/availability remain illustrative until real seller approval.
