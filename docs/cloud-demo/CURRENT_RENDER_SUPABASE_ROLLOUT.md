## Private dashboard preflight (no changes yet)

1. In the existing Render service, open **Settings / Build & Deploy**. Record the currently deployed commit and branch privately. Confirm Docker runtime, root directory `backend`, Dockerfile path `./Dockerfile`, Dockerfile default command, health-check path `/ready`, and the service URL above. Check whether Auto-Deploy is enabled. **Disable or pause Auto-Deploy before an approved branch push**, unless the owner explicitly authorizes a push-triggered deployment and its live Flyway migrations. A branch push is not a safe staging step if Auto-Deploy would immediately apply migrations.
2. In Render **Environment**, verify names and non-secret values: `RIT_ENV=cloud_demo`, `HTTP_HOST=0.0.0.0`, `RIT_CLOUD_DEMO_SEED_ENABLED=true`, `DB_POOL_SIZE=2`, `DEMO_SEED_ENABLED` absent/false, and `PORT` left to Render. For the previously approved direct-password customer signup, set `RIT_CLOUD_DEMO_SELF_SIGNUP_ENABLED=true` **only after explicit approval to change provider settings**. It is false by default; customers are immediately active and Student/Faculty affiliation is self-declared, not verified.
3. In Supabase project **rit-canteen → Connect → Session pooler**, privately copy the exact host, port, database and username. Use Session mode, normally port 5432, because it supports persistent IPv4 connections; do not substitute transaction mode port 6543 or guess the username. Confirm the project is active and that this is the project intended for the demo. The server's `DATABASE_URL` must be a JDBC URL of the form `jdbc:postgresql://<exact-session-pooler-host>:<port>/<database>?sslmode=require`; put the exact pooler username in `DATABASE_USER` and the raw password in Render's private `DATABASE_PASSWORD` field. These values must **never** go into Android Gradle properties. `sslmode=require` encrypts transport but does not verify the database certificate's identity; certificate-verified TLS is a later hardening step.
4. Preserve existing `RIT_CLOUD_DEMO_CUSTOMER_EMAIL`, `RIT_CLOUD_DEMO_CUSTOMER_PASSWORD`, `RIT_CLOUD_DEMO_OWNER_EMAIL` and `RIT_CLOUD_DEMO_OWNER_PASSWORD` settings. Do not rotate them as a troubleshooting step: seed-once provisioning does not reset an existing account password. Seller/admin signup is never public.
5. In Supabase SQL Editor, a **read-only** check may inspect `SELECT version, success FROM flyway_schema_history ORDER BY installed_rank DESC LIMIT 6;` and `SELECT count(*) FROM menu_items;`. Do not paste results containing personal data or credentials into chat. Before approved deployment, arrange a normal database backup and check for failed migrations; do not repair, drop, truncate or reset live tables. After deployment, the latest successful version should be `046`, with four active demo sellers and 72 catalog items if the intended seed was enabled. Existing edited rows must be preserved.

## Approval-gated rollout order

1. Review the branch diff and the forward-only V043–V046 migrations. Obtain separate explicit approval for the branch push and for any Render/provider change or live migration. Confirm Auto-Deploy behavior **before** pushing.
2. Push only `feat/rit-verify-complete-backend-integration`; leave `main` and PR #2 untouched. Point the existing Render service at that branch/commit or manually deploy the exact approved commit. Render should build from `backend/Dockerfile`, run Flyway before HTTP, then start the Ktor service. Watch sanitized startup logs for migration failure; never print the environment.
3. After Render says Live, verify read-only `/health`, `/ready`, four-seller catalog and menu responses. The previously missing operating-policy route should return 200; unauthenticated cart and bulk-draft GETs should return 401 (not 404). If any route is absent or readiness fails, stop before distributing the APK.
4. With separately approved disposable hosted accounts only, test signup/duplicate rejection, login/auth/me, versioned cart read/write, idempotent demo checkout and history, and bulk draft persistence. Confirm a second customer cannot see the first customer's records and `paymentVerified` remains false. These are **live database writes** and are not authorized by this handoff alone.
5. Install the cloud debug APK built with `./gradlew -PritCloudDemo=true -PritApiBaseUrl=https://rit-canteen-cloud-demo.onrender.com :app:assembleDebug`. Unplug USB, remove any ADB reverse mapping, and use mobile data or an independent Wi-Fi network. Force-stop/reopen to verify the same server account, cart and order IDs. Seller access must come from private server provisioning, not a UI role selection. See [phone acceptance](../integration/ANDROID_PHONE_ACCEPTANCE.md).
